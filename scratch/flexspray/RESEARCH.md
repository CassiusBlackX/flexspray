## 2. 主动检验（每条已核实的情况）

- **普通 ECN 分流是否已经够用？**
  - 读混跑：v5.3 的入口打标调度本质上就是 ECN 分流用在 READ 请求的平面选择上。增益真实，但对权重敏感。
  - 1/4 lane 降速：**不够**。分流只影响新的承诺，故障前已有的承诺被困（FEASIBILITY §4.1）。
- **优势是否来自已修复的实现缺陷或仲裁？**
  - v5.3 的门槛结果与 CAQM、T14、fence 的修复无关：这些修复对两侧一致生效，健康 case 逐位相同。
  - 对照方案在硬断链下的挂死，属于功能差异，单列报告。
- **损失要求的不可达是否只是本拓扑的特例？**
  - 结论只依赖一个结构条件：某设备的流量只能走它与对端共有的平面子集，健康时这个子集已接近饱和，而故障移除的是子集内的一个平面。
  - 任何"端点平面数不同"的多平面系统都会出现，可推广。但这是**分析结论**，不是新机制。

## 3. 候选研究主张（状态）

| # | 主张 | 可被推翻的检验 | 当前证据 | 状态 |
|---|---|---|---|---|
| C1 | 在端点平面数不同的多平面网络中，按设备自身平面数 N 计的"单故障损失 < 1/N"，对"流量局限在共有平面子集上的设备"物理不可行；正确的可达界由共有平面数和健康饱和度决定 | 联合 ε LP 给出 ε > 0，或在同一结构下实测损失 < 1/N_phys | h2d F1far、mixed F4 的 ε* < 0（含可人工核对的容量割）；a2a / d2d 的 ε* > 0 | **有限条件下成立**。需要补充：更多拓扑（不同的 CPU / SSD 平面数）、逐设备 LP 的一般化证明 |
| C2 | 路径退化（多 lane 丢失）下，主要损失来自**健康时没有上界的总承诺**（READ 配额 × 扇入，每个节点约 35 MB）在故障时被困在降速平面上（S3：已接纳、带 PSN、未发出，约 3.5 MB / 方向）；只限制新承诺的机制无法消除它 | 限制总承诺后 1/4 lane 显著改善，而只限制新承诺的机制（SIRD 式逐 TP 反馈、时延目标配额）无效；否则推翻 | **第七轮**：状态分解给出因果；聚合上界把 a2aread 1/4 从 0.19 提高到 0.61–0.81（种子 1、9、10），SIRD 式反馈 0.188（无效），与主张一致 | **成立（有限条件）**。尚缺：不损失健康性能的自适应上界（Homa §3.5 列为未来工作），以及 lane 档位下的 LP 下界 |
| C3 | v5.3 的入口打标 READ 调度，可推广到"请求平面选择与响应拥塞协调"的一般情形 | 权重的有效区间随拓扑或负载漂移；或者与简单 ECN 分流没有区别 | 只在一种负载和拓扑上有效，权重敏感 | **工程改进**，暂不作为独立研究贡献 |

**诚实判断（当前）**：
- 工程目标中有两项未达标，并且已经定位：1/2 和 1/4 lane 降速；按 N_phys 计的 1/N 要求。
- C1 有分析价值。C2 若机制成立，可能成为研究核心。
- 目前证据还**不足以**支撑一篇网络系统论文。

| MRC / 多平面容错报告（arXiv 2605.04333，仅摘要） | 逐包喷洒 + 多平面 + 源路由绕开故障 | 摘要不涉及退化链路、读响应和完成模型 | 无法作为基线实现，只作为背景 |

**第七轮的判断**：
- 两个最接近的接收方 / 请求方驱动设计（Homa、SIRD）都**限制新的承诺**，没有处理在路径退化前已经形成、已经绑定的承诺。
- 本项目的测量表明，后者才是 1/4 lane 损失的主体（FEASIBILITY §5.1）。
- 在本项目里实现的两个对应基线也验证了这一点：
  - 聚合上界有效：它在故障前就限制了承诺的总量；
  - 逐 TP 反馈无效：它只作用于故障后的新承诺。

**第七轮研究价值判断：仍为 C**。工程目标大部分完成，但独立研究贡献仍不足。
- C2 已经从"假说"变成"有因果测量和对照基线支持的有限结论"：
  - 困住工作的是健康时没有上界的总承诺；
  - 限制总承诺有效，只限制新承诺无效。
- 但它要成为研究贡献，还缺一个**不牺牲健康性能**的机制。在现有证据中，任何静态上界都只能在健康和降速之间取舍。
- 下一步可检验的方向：
  - 让上界随可用容量变化，健康时宽、发现退化时收紧。难点在于：故障前形成的承诺依然存在，所以收紧的时机必须早于故障，或者需要配合 S3 迁移；
  - 实现 S3 迁移。
- 没有这两者之一，不应主张论文级贡献。

## 6. 第八轮：相关工作对照的修正与主张检验

### 6.1 `ReadBacklogFeedback` 与完整 SIRD 的对应（修正第七轮表述）

| SIRD 组成（§4.1、§4.2、§4.4） | 本项目的 `ReadBacklogFeedback` |
|---|---|
| 接收方全局授信桶 B | **没有**。由另一个开关 `ReadPortBudgetBytes` 单独提供，而且是按端口，不是按接收方 |
| 按发送方的授信桶（≤ 1×BDP），由两个 AIMD 环决定 | 只有按 TP 的 READ 配额 AIMD，一个环 |
| 发送方拥塞比特（发送方累积授信超过 SThr 时置位） | 响应方 TP 的未发字节超过阈值时，在 READ 响应上置 1 bit，含义相近 |
| 核心网络 ECN 环 | **没有**（由 v5.3 的入口打标调度另行承担） |
| 授信回收（丢失时回收） | 没有单独实现 |
| 授信粒度与启动 | 逐包授信，对比本项目的逐段（16 KB）请求；没有实现启动阶段的处理 |

所以它是**受 SIRD 启发的变体**，只实现了按发送方反馈的一部分。第七轮里它的失败**不能**代表 SIRD 方法本身失效，第七轮"SIRD 式基线无效"的说法收窄为"该变体无效"。

### 6.2 逐项检验第八轮的主张

**主张**："高逻辑并发不应等价于深的路径绑定承诺；合适的接纳边界加合法的晚绑定，能否同时保持健康吞吐，并限制容量下降后的尾段？"

**证据**（FEASIBILITY §6）：
- **根因之一是计时器缺陷，与该主张无关**：固定 RTO 小于降速端口的排队时延，GBN 重传放大了重复数据。修复后，写路径与读路径都大幅改善。这是一个普通的工程修复（与 TCP 的 RTT 自适应 RTO 同理），**不是**研究贡献。
- **只修计时器不够**：a2aread 1/4 只到 0.39，正好接近故障时状态的下界 0.46。这说明余下的损失来自承诺深度。
- **总承诺上界 + 返回速率调度 + 晚接纳（路线 A）**把 a2aread 1/4 提高到 0.84，同时健康 a2aread 从 0.965 提高到 0.975。在已试的 B 中，健康与降速在 1.5 MB 时同时满足。
- **相对既有机制的必要性**（消融，FEASIBILITY §6.4）：
  - 只有聚合预算（第七轮 / Homa §3.5 式）会产生慢平面重定向；
  - 只有晚接纳会放大请求接纳；
  - 只有返回速率分数，在没有预算时会使 mixedread 1/2 变差。
  - 三者组合，才在所测负载上同时满足。

**仍然缺少的证据**：
- 不同扇入、平面集合、RTT、缓冲上的系统性推广：只测了一个拓扑族，另加超额订阅与规模 / 时刻变化，见 FEASIBILITY §6.5；
- B 的选择依据：目前是试出来的，B 敏感（3 MB 时 1/4 降到 0.56）。虽然有一个可解释的上界 eff ≲ T / (t_f + B / C_deg)，但还没有在线选 B 的方法；
- 3/4 近端 a2aread 下降 3 pp（由预算造成），原因未查明。

**判断**：
- 本轮形成的是一套**可解释的工程机制组合**，加一个关于"承诺深度—降速尾段"的定量关系。
- 把它作为独立研究贡献，还需要：
  - 在线选择 B，或者用 S3 迁移替代 B；
  - 更多拓扑和平面集合上的系统证据。
- **当前仍为 C**（工程优化为主），但比第七轮更接近一个可检验的研究问题。

## 7. 第九轮：在合理重传基线上重新判断（FEASIBILITY §7）

**修正此前的正文**：
- 第七、八轮的"静态预算无法同时满足"与"承诺被困是主因"都已修正，历史记录保留。
- 第八轮把 RTO 修正和读侧机制合在一起，作为"候选 C"的收益来报告，**高估了读侧机制的作用**。本节以 B1（B0 + 公共 RTO 修正）为起点。

**逐项回答**：

1. **在 B1 上，降速损失是否仍主要来自承诺与绑定？**
   - **读方向是**：B1 下 a2aread 1/4 只有 0.39 / 0.45，限制总承诺（B）后提高到 0.83–0.87。
   - **写方向不是**：B1 下 a2a 1/4 已经到 0.85 / 0.87，剩余的 Δ（14–19 µs）来自**故障后**向慢平面新增的承诺（§7.6），不是故障前的绑定。
   - **短任务**：故障时的状态才是主要约束（a2aread ×0.5：实际 131 µs，对比不迁移时的状态界 125 µs）。
2. **新机制是否明显优于简单方案？**
   - 在 B1 上，读侧最小的有效组合是 M = B + Q + L+S：Q 的作用是**补偿 B**（修复 B 转向慢平面的问题），L+S 只有小幅收益；D 带来 3 项回退，已去除。
   - 也就是说，有效的部分是一个**带公平与返回速率分发的聚合读授信**，与 Homa §3.5 / §3.6 的受控超额承诺属于同一类思想。新意在于：在多平面、读响应、lane 降速的条件下，必须配套"返回速率分数"，否则预算会把请求推向慢平面。
3. **是否存在可推广的健康吞吐—恢复尾段权衡？**
   - 存在，但只在读方向上有清晰证据：B 越大，健康越好、1/4 越差（第八轮 §6.4）。
   - 这一关系的机制是故障时被困的 Q_S3 + Q_S4，而不是 B 本身（§7.6）。
   - 它适用的条件：作业规模相对 B 足够大、故障不过晚、慢口是请求方自己的端口或单个响应方的端口。
4. **是否有有限资源、正确性和稳定性方面的独立设计？**
   - 预算：按端口一个计数器加一个等待队列；Q：按 TP 两个变量。
   - 正确性：P1–P6 全部通过（§7.8）。
   - 稳定性：没有在线自适应，所以不存在控制环稳定性的问题；但这同时意味着 B 是试出来的，没有在线选择的依据。

**判断：C（主要收益来自公共修正，独立研究机制仍不足）**。
- B1 是一个普通但必要的工程修复（与已有协议的 RTT 自适应 RTO 同理，加上 Karn 规则），它单独收回了写路径大部分损失、读路径一半的损失，**不能**作为新机制的创新点。
- 在 B1 上，读侧机制仍有大的、真实的收益（1/4：0.39 → 0.87），但：
  - 它跌破了一个原本通过的门槛（a2aread 3/4 近端）；
  - 1/2、1/4 仍未全部达标；
  - 写方向的着力点（故障后分发）还没有无回退的机制。
- 在这些问题解决之前，不主张论文级贡献。
