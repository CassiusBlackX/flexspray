## 2. 主动检验（每条已核实的情况）

- **普通 ECN 分流是否已经够用？**
  - 读混跑：v5.3 的入口打标调度本质上就是 ECN 分流用在 READ 请求的平面选择上。增益真实，但对权重敏感。
  - 1/4 lane 降速：**不够**。分流只影响新的承诺，故障前已有的承诺被困（FEASIBILITY §4.1）。
- **优势是否来自已修复的实现缺陷或仲裁？**
  - v5.3 的门槛结果与 CAQM、T14、fence 的修复无关：这些修复对两侧一致生效，健康 case 逐位相同。
  - 对照方案在硬断链下的挂死，属于功能差异，单列报告。
- **损失要求的不可达是否只是本拓扑的特例？**
  - 结论只依赖一个结构条件：某设备的流量只能走它与对端共有的平面子集，健康时这个子集已接近饱和，而故障移除的是子集内的一个平面。
  - 任何"端点平面数不同"的多平面系统都会出现，可推广。但这是**分析结论**，不是新机制。

- 工程目标中有两项未达标，并且已经定位：1/2 和 1/4 lane 降速；按 N_phys 计的 1/N 要求。

**第七轮的判断**：
- 两个最接近的接收方 / 请求方驱动设计（Homa、SIRD）都**限制新的承诺**，没有处理在路径退化前已经形成、已经绑定的承诺。
- 本项目的测量表明，后者才是 1/4 lane 损失的主体（FEASIBILITY §5.1）。
- 在本项目里实现的两个对应基线也验证了这一点：
  - 聚合上界有效：它在故障前就限制了承诺的总量；
  - 逐 TP 反馈无效：它只作用于故障后的新承诺。

**第七轮研究价值判断：仍为 C**。工程目标大部分完成，但独立研究贡献仍不足。
- C2 已经从"假说"变成"有因果测量和对照基线支持的有限结论"：
  - 困住工作的是健康时没有上界的总承诺；
  - 限制总承诺有效，只限制新承诺无效。
- 但它要成为研究贡献，还缺一个**不牺牲健康性能**的机制。在现有证据中，任何静态上界都只能在健康和降速之间取舍。
- 下一步可检验的方向：
  - 让上界随可用容量变化，健康时宽、发现退化时收紧。难点在于：故障前形成的承诺依然存在，所以收紧的时机必须早于故障，或者需要配合 S3 迁移；
  - 实现 S3 迁移。
- 没有这两者之一，不应主张论文级贡献。

## 6. 第八轮：相关工作对照的修正与主张检验

### 6.1 `ReadBacklogFeedback` 与完整 SIRD 的对应（修正第七轮表述）

| SIRD 组成（§4.1、§4.2、§4.4） | 本项目的 `ReadBacklogFeedback` |
|---|---|
| 接收方全局授信桶 B | **没有**。由另一个开关 `ReadPortBudgetBytes` 单独提供，而且是按端口，不是按接收方 |
| 按发送方的授信桶（≤ 1×BDP），由两个 AIMD 环决定 | 只有按 TP 的 READ 配额 AIMD，一个环 |
| 发送方拥塞比特（发送方累积授信超过 SThr 时置位） | 响应方 TP 的未发字节超过阈值时，在 READ 响应上置 1 bit，含义相近 |
| 核心网络 ECN 环 | **没有**（由 v5.3 的入口打标调度另行承担） |
| 授信回收（丢失时回收） | 没有单独实现 |
| 授信粒度与启动 | 逐包授信，对比本项目的逐段（16 KB）请求；没有实现启动阶段的处理 |

所以它是**受 SIRD 启发的变体**，只实现了按发送方反馈的一部分。第七轮里它的失败**不能**代表 SIRD 方法本身失效，第七轮"SIRD 式基线无效"的说法收窄为"该变体无效"。

### 6.2 逐项检验第八轮的主张

**主张**："高逻辑并发不应等价于深的路径绑定承诺；合适的接纳边界加合法的晚绑定，能否同时保持健康吞吐，并限制容量下降后的尾段？"

**证据**（FEASIBILITY §6）：
- **根因之一是计时器缺陷，与该主张无关**：固定 RTO 小于降速端口的排队时延，GBN 重传放大了重复数据。修复后，写路径与读路径都大幅改善。这是一个普通的工程修复（与 TCP 的 RTT 自适应 RTO 同理），**不是**研究贡献。
- **只修计时器不够**：a2aread 1/4 只到 0.39，正好接近故障时状态的下界 0.46。这说明余下的损失来自承诺深度。
- **总承诺上界 + 返回速率调度 + 晚接纳（路线 A）**把 a2aread 1/4 提高到 0.84，同时健康 a2aread 从 0.965 提高到 0.975。在已试的 B 中，健康与降速在 1.5 MB 时同时满足。
- **相对既有机制的必要性**（消融，FEASIBILITY §6.4）：
  - 只有聚合预算（第七轮 / Homa §3.5 式）会产生慢平面重定向；
  - 只有晚接纳会放大请求接纳；
  - 只有返回速率分数，在没有预算时会使 mixedread 1/2 变差。
  - 三者组合，才在所测负载上同时满足。

**仍然缺少的证据**：
- 不同扇入、平面集合、RTT、缓冲上的系统性推广：只测了一个拓扑族，另加超额订阅与规模 / 时刻变化，见 FEASIBILITY §6.5；
- B 的选择依据：目前是试出来的，B 敏感（3 MB 时 1/4 降到 0.56）。虽然有一个可解释的上界 eff ≲ T / (t_f + B / C_deg)，但还没有在线选 B 的方法；
- 3/4 近端 a2aread 下降 3 pp（由预算造成），原因未查明。

**判断**：
- 本轮形成的是一套**可解释的工程机制组合**，加一个关于"承诺深度—降速尾段"的定量关系。
- 把它作为独立研究贡献，还需要：
  - 在线选择 B，或者用 S3 迁移替代 B；
  - 更多拓扑和平面集合上的系统证据。
- **当前仍为 C**（工程优化为主），但比第七轮更接近一个可检验的研究问题。

## 7. 第九轮：在合理重传基线上重新判断（FEASIBILITY §7）

**修正此前的正文**：
- 第七、八轮的"静态预算无法同时满足"与"承诺被困是主因"都已修正，历史记录保留。
- 第八轮把 RTO 修正和读侧机制合在一起，作为"候选 C"的收益来报告，**高估了读侧机制的作用**。本节以 B1（B0 + 公共 RTO 修正）为起点。

**逐项回答**：

1. **在 B1 上，降速损失是否仍主要来自承诺与绑定？**
   - **读方向是**：B1 下 a2aread 1/4 只有 0.39 / 0.45，限制总承诺（B）后提高到 0.83–0.87。
   - **写方向不是**：B1 下 a2a 1/4 已经到 0.85 / 0.87，剩余的 Δ（14–19 µs）来自**故障后**向慢平面新增的承诺（§7.6），不是故障前的绑定。
   - **短任务**：故障时的状态才是主要约束（a2aread ×0.5：实际 131 µs，对比不迁移时的状态界 125 µs）。
2. **新机制是否明显优于简单方案？**
   - 在 B1 上，读侧最小的有效组合是 M = B + Q + L+S：Q 的作用是**补偿 B**（修复 B 转向慢平面的问题），L+S 只有小幅收益；D 带来 3 项回退，已去除。
   - 也就是说，有效的部分是一个**带公平与返回速率分发的聚合读授信**，与 Homa §3.5 / §3.6 的受控超额承诺属于同一类思想。新意在于：在多平面、读响应、lane 降速的条件下，必须配套"返回速率分数"，否则预算会把请求推向慢平面。
3. **是否存在可推广的健康吞吐—恢复尾段权衡？**
   - 存在，但只在读方向上有清晰证据：B 越大，健康越好、1/4 越差（第八轮 §6.4）。
   - 这一关系的机制是故障时被困的 Q_S3 + Q_S4，而不是 B 本身（§7.6）。
   - 它适用的条件：作业规模相对 B 足够大、故障不过晚、慢口是请求方自己的端口或单个响应方的端口。
4. **是否有有限资源、正确性和稳定性方面的独立设计？**
   - 预算：按端口一个计数器加一个等待队列；Q：按 TP 两个变量。
   - 正确性：P1–P6 全部通过（§7.8）。
   - 稳定性：没有在线自适应，所以不存在控制环稳定性的问题；但这同时意味着 B 是试出来的，没有在线选择的依据。

**判断：C（主要收益来自公共修正，独立研究机制仍不足）**。
- B1 是一个普通但必要的工程修复（与已有协议的 RTT 自适应 RTO 同理，加上 Karn 规则），它单独收回了写路径大部分损失、读路径一半的损失，**不能**作为新机制的创新点。
- 在 B1 上，读侧机制仍有大的、真实的收益（1/4：0.39 → 0.87），但：
  - 它跌破了一个原本通过的门槛（a2aread 3/4 近端）；
  - 1/2、1/4 仍未全部达标；
  - 写方向的着力点（故障后分发）还没有无回退的机制。
- 在这些问题解决之前，不主张论文级贡献。

## 8. 第十轮：统一服务时间模型的研究判断（FEASIBILITY §8）

**可以主张的**（有本轮证据）：
- **共同结构**：降 lane 时，受损设备的承诺按字节限制（每 TP 流水段数、每端口 READ 字节预算），慢端口因此承诺了 1.3–4 倍于快端口的排空时间；控制消息（READ 请求）按 PSN 顺序排在其后。
- 这比第九轮"故障后新增承诺 / 请求发得晚"更具体，并且有逐单元的因果链（§8.1–8.3）。
- 写方向：同一个完成时间估计（出发 + 在途 + 发送后残差，残差带 Karn 规则和衰减）在 B1 / M 之上把 a2a 1/4 从 Δ +18 / +14 µs 变为 −7 / −4 µs，并且没有恢复第九轮 W 项"永久弃用慢平面"的问题。代价是 h2d −4 pp，来自残差，原因待查（T19f）。

**不能主张的**：
- **"统一机制同时解决读写"**：S4 在 mixedread 1/4 上比 M 差，并且不过门槛。读侧 1/4 的大部分收益需要频繁的响应改绑，而这一路径在硬断时有无法恢复的协议缺陷（§8.5）。
- **作为默认或验收版本**：S4 违反了"相对 B1 / M 不差 1 pp"的保护条件。

**与 SIRD 的关系**：
- 本轮的读预算仍然是按本地链路速率换算的时间预算，不使用实测服务率。原因是 μ 取实测值时，B = μ(R + τ) 有正反馈（§8.4）。
- SIRD 在接收方协调总授信与各发送方的可用服务，本轮没有实现这一部分（参见 §6.1 的对应表）。

**判断：研究价值仍为 C**。工程上写方向有实质进展，读方向受协议缺陷阻断。只有在修复晚绑定响应的可恢复性（T19e）之后，如果同一估计仍能同时改善读写且没有回退，才有理由主张独立贡献。

## 9. 贡献候选（按 CLAUDE.md §1 记录；不是投稿主张）

### 9.1（第十二轮降级并检验）降 lane 的完成时间损失远离物理界；拖尾每阶段复现【有限条件下成立：benchmark v1、本拓扑】

**降级原因**（独立评审，`work/REVIEW_judge_round11.md` 第 2 节）：
- 第十一轮写的"稳态损失 = 移除容量"近乎同义反复：只要其余端口保持忙碌，设备吞吐就等于端口速率之和。
- 稳态窗口截止在 80% 字节点，按定义排除了拖尾。
- 被记为 n/a 的行恰好包含最差的行。

**保留的现象**：
- 完成时间损失远离物理界：默认 a2aread x1 为 81.8%，LP 下界 4.0%。
- 第十轮测到两个来源：故障前的承诺被困（一次性），以及故障后仍按字节承诺（每阶段都会复现）。

**可被推翻的检验**：在多阶段、带屏障的负载上计算故障后每阶段完成时间相对 LP 的膨胀（第十二轮）。
- 只有跨越故障的那个阶段膨胀，即为一次性拖尾；
- 之后每个阶段都膨胀，即为每阶段复现。

**第十二轮检验结果**（FEASIBILITY §10.3）：**每阶段复现**。
- 默认配置下，ring 与 MoE 在 x2 / x1 下每个故障后阶段超出容量损失 21–77%，原因是故障后的分配仍按字节承诺。
- 在本负载上，这是"承诺以时间计"这条主线的必要条件；候选 C 部分降低了它。
- 仍需公开拓扑与敏感性分析（T26）才能推广。

**与已读文献的差别**：未核对。

### 9.2 1/N 在 N = 总 lane 数下对丢 ≥ 2 条 lane 物理不可达；对 1 条 lane 恰好在界上【已实现并验证】

- 丢 k 条 lane 时，移除的设备容量是 k/(4·N_dev)。在设备受端口限制时，k ≥ 2 的损失下界 ≥ 2/(4·N_dev) > 1/(4·N_dev)。
- 实测在稳态窗口与下界一致。
- **证据**：`lm/table_lt.md`、`table_le.md`。
- **可被推翻的检验**：受损设备不受端口限制（需求 < 容量）的负载上，这一下界不成立，那时应按 LP 判定。

### 9.3 单链路叶脊结构中的喷洒黑洞：端到端探测成功，同时 GBN 活锁【已实现并验证】

**现象**：
- lpp = 1 时，spine 失去唯一的下行链路后，继续接收上游喷来的包并丢弃。
- 端侧探测走其他 spine，所以都能成功；每次 ACK 有进展都会重置 GBN 的次数上限，于是没有 TP 被判死，作业不完成。默认配置同样如此。

**修复**：逐跳的 fabric 路由撤回（68aeeb91）。

**可被推翻的检验**：
- lpp ≥ 2 时不应出现（18 个抽样运行逐位相同，已验证）；
- 撤回延迟在 2–200 µs 内都应能完成（已验证）。

**与文献**：属于 gray failure 一类问题，相关文献本轮**没有读原文**，未核对差别。

### 9.4 降 lane 下的拖尾来自"按字节承诺"；把每一种端点承诺都改成按排空时间计，可消除旧矩阵上全部可行的失败行【有限条件下成立，自定义负载】

**现象**（第十三轮，FEASIBILITY §11.2）：
- 端点有三种承诺：端口已接纳未发、READ 授信、承诺单位（段）。
- 只把端口承诺改为时间上限（PortCommitDelay）不够：READ 授信仍是 1.5 MB，即 30 µs 的排空时间，远大于阶段时长。
- 把 READ 授信改为 8 µs（400 KB，按端口速率缩放）后，旧矩阵上读侧 x1 失败全部消失：a2aread x1 从 B1 的 62.4 / 56.7% 降到 11.0 / 11.4%。
- 候选 D 在 28 个 x2 / x1 行上只剩 1 行失败，而那 1 行由逐设备 LP 证明物理不可行；健康全部在 B1 的 1 pp 内。

**仍不成立的部分**：
- 固定的 8 µs READ 预算在失去端口时有害：a2aread 的 F1 / F4 / H1 比 B1 差 6–8 pp，H4 不过（FEASIBILITY §11.5）。"按时间计"必须用**当前**可用容量换算，而不能只按端口线速一次性换算。
- 承诺单位（16 KB 段）仍按字节计。短阶段负载（MoE）里，N 个发送端各自至少把一个段送进同一个降速远端口，拖尾每阶段复现（12–50%）。
- 小段能消除这一拖尾，但会给长作业带来健康代价。按端口速率缩放段长（时间量子）需要协议改动（TODO T30）。

**证据**：`<work>/exp/round13/{rb,tw,ds,seg,joint,dep,cmb}`，`hb/ds_lm.jsonl`、`hb/ds_pi.jsonl`。

**可被推翻的检验**：
- 在未见种子 / 映射 / 规模上，D 的 x2 / x1 可行行若有失败，即推翻"全部可行行通过"；
- 若 READ 预算在 8 µs 附近的效果对负载敏感（例如某些负载需要 ≥ 30 µs 才不损失健康性能），则"统一时间常数"的说法不成立。

**与已读文献的差别**：
- Homa §3.5 的超额承诺程度按消息数计，SIRD §4.1–4.2 的授信桶按 BDP（字节）计。本项目的数据表明，在路径容量下降时，字节计的预算会变成过长的排空时间。
- 是否已有工作把"承诺以时间计"作为多平面降级下的统一原则，**未核对**（未检索新文献）。

### 9.5 短阶段集合通信的"带宽上限"必须计入路径时延，否则会把物理限制误判为实现不足（或反之）【已实现并验证】

- 纯带宽 LP 判 ring 步 0.67，计入实测基础时延后为 0.98。MoE dispatch 0.83 → 0.84，而时延感知的时隙 LP 证明 18.56 µs 可达、实测 21.97 µs，说明缺口是实现问题（T29）。
- 方法：实测空网络单报文完成时间得到 α；阶段上界 = max(LP + α_min, 各流单独 + α_f)；再用时隙 LP 判定可达性，所有取整朝放松方向，所以是有效下界。
- **证据**：`flexspray_dagbound.py`、`flexspray_shiftlp.py`，`<work>/exp/round13/{lat,hb,hsz}`。
- **可被推翻的检验**：时延感知 LP 给出的下界若被某个实测运行打破，说明模型有误。
