# 优化初始化、内存和查路由

优化规则编译、共享存储、本地端口组索引和运行时查询，避免字符串处理和动态图算法进入
逐包路径。

验收：量化冷启动、峰值 RSS、常驻路由内存和查路由延迟，并与表路由及第一阶段比较。

完成情况：C++ 运行时按当前节点预索引，精确规则使用哈希查询，范围规则按目的端口分组并
二分查找；安装阶段预解析端口组，`PrepareForLookup()` 后释放安装期对象。64-NPU 冷编译从全表的
1.03 s 降至 mixed 的 0.283 s，实际仿真子进程峰值 RSS 从 68,468,736 bytes 降至
63,389,696 bytes。查找微基准显示表和精确规则约 6.6 至 7.8 ns，范围规则约 8.9 至
10.7 ns；查找延迟没有显著收益，主要收益是生成时间和内存。

后续补充：运行时加入 `UbTopologyNextHopIndex`，生命周期入口改为
`PrepareForLookup()`。1024-NPU 全量验证覆盖 9,427,968 个目的端口查询和 2,145,280 个节点
主地址查询。现有 endpoint workload 的候选查询从约 7,111 ns 降至 820 ns，`GetOutPort`
从约 7,158 ns 降至 1,047 ns。索引增加约 4.34 MiB RSS，规则模式相对完整表仍节省约
86.3%。完整结果见 `topology-next-hop-index-report.md`。
