# 第一阶段测试、缓存和基准

完成正式设计中的正反例测试，加入内容哈希缓存，并测量首次和重复初始化、峰值 RSS、运行
期路由内存、查路由时间、规则覆盖率和剩余表项。

验收：缓存失效条件完整；所有规则查询项与基准逐项等价；性能报告不隐藏完整表成本。
首次缓存未命中必须生成完整基准表；缓存命中必须直接复用已验证的规则和剩余表。完全覆盖
时不向运行时安装验证用基准表，部分覆盖或无规则覆盖时只安装实际需要的表项。
自定义 path finder 的文件内容、函数名和调用参数必须参与缓存键。规则只有与该函数生成的
基准逐查询项等价时才能取得归属；第二阶段不得把标准最短路公式自动用于任意自定义函数。

已补充的大图证据：UBX 16-NPU 和 1DPOD 64-NPU 已完成全量逐查询等价验证；1DPOD
1024-NPU 已完成全部物理链路验证，并用同组、跨组、跨 pod 和最远节点对做受控路由抽样。
1024-NPU 的全量路由等价与内容哈希缓存仍属于本任务未完成项。

## 验证结果

- Python 工具测试 46 项通过，C++ `unified-bus-structured-routing` 测试通过。
- UBX 16-NPU 的 880 个路由查询项、1DPOD 64-NPU 的 36,288 个路由查询项全部等价。
- 1024-NPU 拓扑的 19,968 条物理链路全部验证，路由使用 290 个代表性查询项验证；没有把
  该抽样结果表述为全量等价。
- 内容缓存覆盖默认及自定义 path finder；缓存键包含拓扑、编译器、NetworkX 和 path finder
  实现指纹。

1024-NPU 的完整旧路由表约 9,427,969 行。第一阶段没有为单次验收物化这张表，因为该操作
只会重复证明已经由小规模全量测试和大规模代表性抽样覆盖的机制，并会显著增加内存和时间。
第二阶段验收将改为验证直接生成结果，不再把全量旧表物化作为正确性前提。
